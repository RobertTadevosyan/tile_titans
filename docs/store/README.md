# Store package — Tile Titans (`lets.play.game`)

Target: **Google Play**. Everything here is regenerated by the commands below;
nothing is hand-edited in place.

## Contents

| Path | What | Rebuild with |
|---|---|---|
| `listing/<lang>.md` | Title, short and full description, 10 languages | `python3 tool/store/listings.py` |
| `../../build/store/icon/icon_512.png` | Play listing icon, 512×512 | `flutter test test/store_icon_test.dart --tags store` |
| `video/gameplay_1080x2404.mp4` | Raw gameplay, no frame, no ads | see **Gameplay capture** |

The launcher icon itself lives in the app (`assets/icons/app_icon.png` plus the
generated Android/iOS sets) and is produced by the same icon test followed by
`dart run flutter_launcher_icons`.

## Gameplay capture

Ads are silenced at **compile time**, never at runtime — a runtime switch can
leak into a release and a reviewer can find it:

```sh
flutter build apk --release --target-platform android-arm64 \
  --dart-define=STORE_CAPTURE=true
```

`STORE_CAPTURE` is read only by `adsEnabled()` in `lib/utils/helper.dart`, which
every banner and the interstitial service consult. A normal build has ads; a
test asserts that default so a capture build cannot become the shipping one.

Record on an emulator booted with a **hardware GPU** — with `swiftshader` the
recording comes out at 18 fps and looks broken:

```sh
emulator -avd Pixel_9_Pro_XL -no-snapshot-save -gpu host
adb shell "nohup screenrecord --size 1080x2404 --bit-rate 16000000 \
  --time-limit 40 /sdcard/gp.mp4 >/dev/null 2>&1 &"
# drive gameplay, then WAIT for screenrecord to exit before pulling:
# it writes the moov atom on exit, and a file pulled early will not play.
```

Encode with the store-safe flags:

```sh
ffmpeg -i gp.mp4 -r 30 -c:v libx264 -pix_fmt yuv420p -profile:v high \
  -crf 17 -preset slow -movflags +faststart -an -y \
  docs/store/video/gameplay_1080x2404.mp4
```
